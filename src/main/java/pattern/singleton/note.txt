单例模式是一种创建型设计模式，确保一个类只有一个实例，并提供一个全局访问点来获取该实例。

核心要求：
私有构造函数：防止外部 new。
静态私有实例：持有唯一对象。
公共静态方法：提供全局访问入口（如 getInstance()）。
💻 常见实现方式（由简到繁）
1️⃣ 饿汉式（Eager Initialization）✅ 推荐（简单场景）
java
编辑
public class EagerSingleton {
    // 类加载时就创建实例（线程安全）
    private static final EagerSingleton INSTANCE = new EagerSingleton();

    // 私有构造函数
    private EagerSingleton() {}

    public static EagerSingleton getInstance() {
        return INSTANCE;
    }
}
✅ 优点：线程安全、实现简单、无同步开销。
❌ 缺点：即使不用也会创建实例，可能浪费资源。
✅ 适用：实例占用资源少，或一定会被使用。
2️⃣ 懒汉式（Lazy Initialization）❌ 不推荐（非线程安全）
java
编辑
public class LazySingleton {
    private static LazySingleton instance;

    private LazySingleton() {}

    // ❌ 多线程下可能创建多个实例！
    public static LazySingleton getInstance() {
        if (instance == null) {
            instance = new LazySingleton();
        }
        return instance;
    }
}
⚠️ 不要在多线程环境中使用此写法！

3️⃣ 双重检查锁定（Double-Checked Locking）✅ 推荐（高性能懒加载）
java
编辑
public class DCLSingleton {
    // volatile 禁止指令重排序，保证可见性
    private static volatile DCLSingleton instance;

    private DCLSingleton() {}

    public static DCLSingleton getInstance() {
        if (instance == null) { // 第一次检查
            synchronized (DCLSingleton.class) {
                if (instance == null) { // 第二次检查
                    instance = new DCLSingleton();
                }
            }
        }
        return instance;
    }
}
✅ 优点：延迟加载 + 线程安全 + 高性能（仅首次加锁）。
✅ 关键：必须用 volatile 防止 JVM 指令重排导致返回未初始化对象。
4️⃣ 静态内部类（Initialization-on-Demand Holder）✅ 强烈推荐
java
编辑
public class StaticHolderSingleton {
    private StaticHolderSingleton() {}

    // 利用类加载机制保证线程安全和懒加载
    private static class Holder {
        static final StaticHolderSingleton INSTANCE = new StaticHolderSingleton();
    }

    public static StaticHolderSingleton getInstance() {
        return Holder.INSTANCE;
    }
}
✅ 优点：
线程安全（JVM 保证类加载原子性）
延迟加载（只有调用 getInstance() 才触发 Holder 类加载）
无锁、性能高、代码简洁
✅ 业界最推荐写法之一
5️⃣ 枚举单例（Enum Singleton）✅ 最安全（防反射/序列化攻击）
java
编辑
public enum EnumSingleton {
    INSTANCE;

    public void doSomething() {
        System.out.println("执行业务逻辑");
    }
}

// 使用方式
EnumSingleton.INSTANCE.doSomething();
✅ 优点：
天然线程安全
防止反射攻击（无法通过 newInstance() 创建）
防止反序列化破坏单例（Java 枚举序列化机制特殊）
✅ 《Effective Java》作者 Joshua Bloch 强烈推荐
❌ 缺点：不能继承其他类（但可实现接口）
🔒 线程安全对比
实现方式	线程安全	延迟加载	防反射	防序列化
饿汉式	✅	❌	❌	❌
懒汉式（无锁）	❌	✅	❌	❌
双重检查	✅	✅	❌	❌
静态内部类	✅	✅	❌	❌
枚举	✅	✅	✅	✅
💡 若需绝对安全（如金融系统），优先选择枚举单例。

⚠️ 单例的潜在问题
1. 反射攻击破坏单例
java
编辑
Constructor<Singleton> c = Singleton.class.getDeclaredConstructor();
c.setAccessible(true);
Singleton s1 = c.newInstance(); // 绕过私有构造函数！
解决方案：在构造函数中加判断，或使用枚举。
2. 序列化破坏单例
如果单例类实现了 Serializable，反序列化会创建新实例。
解决方案：
java
编辑
private Object readResolve() {
    return INSTANCE; // 返回唯一实例
}
但枚举无需此操作！

3. 违背单一职责原则
单例类既要管理业务逻辑，又要管理自身生命周期。
4. 难以测试
全局状态影响单元测试的隔离性。
✅ 最佳实践建议
场景	推荐实现
普通工具类（如配置管理）	静态内部类 或 饿汉式
高并发环境	双重检查 或 静态内部类
安全敏感系统（防攻击）	枚举单例
Spring 中的 Bean	默认就是单例（由容器管理，无需手动实现）
🌰 实际应用案例
日志记录器（Logger）：全局唯一写入日志。
配置管理器（ConfigManager）：读取一次配置，全局共享。
数据库连接池：通常由单例管理连接资源。
Spring 的 Bean（默认 scope=singleton）。
💡 总结
单例模式不是“禁止创建多个对象”，而是“控制实例数量为一”。

在现代开发中，依赖注入（如 Spring）往往比手动实现单例更灵活、更易测试。

但如果必须手动实现，请优先考虑：

枚举单例（最安全）
静态内部类（平衡性能与简洁）
合理使用单例，避免滥用（如将所有类都做成单例），才能发挥其真正价值。
