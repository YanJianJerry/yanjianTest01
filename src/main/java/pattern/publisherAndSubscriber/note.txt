在 Java 中，发布者-订阅者模式（Publisher-Subscriber Pattern） 是一种消息传递模式，常用于解耦消息的发送方（发布者）和接收方（订阅者）。它与观察者模式非常相似，但通常更强调异步通信、事件总线（Event Bus） 或 消息队列 的概念，适用于更复杂的系统（如事件驱动架构、消息中间件等）。

下面我将通过一个轻量级、线程安全、基于事件总线的发布-订阅模式的 Java 实现来演示这一模式，并附上详细注释。

🧩 场景说明
发布者（Publisher）：发布某种类型的消息（事件）。
订阅者（Subscriber）：订阅特定类型的消息，并在消息到达时处理它。
事件总线（Event Bus）：作为中介，管理订阅关系并分发事件。

🔍 发布者-订阅者 vs 观察者模式的区别
特性	观察者模式	发布-订阅模式
耦合度	主题与观察者直接知道对方	通过事件总线完全解耦
通信方式	通常是同步	通常支持异步
中介	无（直接调用）	有（事件总线/消息队列）
适用场景	GUI 事件、简单通知	分布式系统、事件驱动架构
🚀 扩展建议
使用 Guava EventBus 或 Spring Event 可快速实现生产级发布订阅。
在分布式系统中，可用 Kafka / RabbitMQ / Redis Pub/Sub 实现跨进程发布订阅。
添加 事件过滤、优先级、死信队列 等高级特性。
这个实现展示了 Java 中如何手动构建一个线程安全、类型安全、支持异步的发布-订阅系统，适合学习和中小型项目使用。
