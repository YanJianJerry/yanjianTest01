🔧 Java 中的实现方式
Java 提供了 Cloneable 接口和 Object.clone() 方法来支持原型模式。

但要注意：clone() 是浅拷贝，若对象包含引用类型字段，需手动实现深拷贝。

我们希望快速生成多个相同类型的怪物，避免重复初始化。

🔍 原型模式 vs 直接 new
方式	优点	缺点
new + 构造函数	简单直观	每次都要重新初始化，成本高
原型模式（clone）	避免重复初始化，性能高
隐藏创建细节	需实现 Cloneable
深拷贝实现复杂
⚠️ 注意事项
Cloneable 是一个“标记接口”，不包含方法，但必须实现才能调用 clone()。
默认 clone() 是浅拷贝：对引用类型字段只是复制引用，不是新对象。
深拷贝需手动处理：递归克隆所有可变引用对象。
替代方案：
使用 序列化/反序列化 实现深拷贝（简单但性能低）。
使用 拷贝构造函数（public Monster(Monster other)）—— 更安全、更灵活，推荐！
💡 拷贝构造函数实现（推荐替代 clone）
java
编辑
class Monster {
    // 拷贝构造函数
    public Monster(Monster other) {
        this.name = other.name;
        this.health = other.health;
        this.attack = other.attack;
        this.weapon = new Weapon(other.weapon.getName(), other.weapon.getDamage());
    }
}
✅ 优点：类型安全、无需强制转换、可被继承、无异常风险。

🌐 实际应用案例
游戏开发：快速生成大量相同敌人/NPC。
图形编辑器：复制复杂图形对象（如带样式的图表）。
缓存系统：返回缓存对象的副本，避免外部修改污染缓存。
Spring 框架：prototype 作用域 Bean 每次获取都是新实例，但内部可能基于原型复制。
✅ 总结
原型模式 = 通过克隆现有对象来创建新对象

它适用于对象创建成本高或需要动态配置对象的场景。

在 Java 中，优先考虑 拷贝构造函数 或 深拷贝工具类，谨慎使用 clone()。

合理使用原型模式，可以显著提升系统性能并简化对象创建逻辑。
